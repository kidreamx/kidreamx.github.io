Troubleshooting

1. AI 이미지 분석 속도 20배 향상

? 기존 동기 방식의 이미지 분석 로직에서 100장의 이미지를 처리하는 데 20분이 소요되고, 다수 사용자 접속 시 병목 현상이 발생하는 문제를 확인했습니다.

Kafka와 Zookeeper를 활용해 분산 처리 시스템 구축

  • Kafka와 Zookeeper를 도입하여 비동기 이벤트 기반 아키텍처로 재설계. Topic 파티션을 20개로 확장하고 Consumer 스레드도 20개로 증설하여 병렬 처리 환경 구성
  • 작업 처리 속도를 기존 대비 20배 향상, 10명의 동시 사용자 요청에 대해서도 10배 빠른 응답 속도를 확보하여 서비스 안정성을 높임
2. 상황에 따른 파라미터 빌드를 통한 개발 효율성 향상

? Dev 수정 후 머지할 때 서버가 멈추는 문제 발생 — 빌드시 모든 도커 container가 재시작되는 파이프라인으로 인해 FrontEnd·BackEnd 연동 작업이 불편했습니다.

개발 파트별로 따로 빌드를 진행할 수 있는 파라미터 빌드 파이프라인을 구축하여 해결

  • AI, BackEnd(SpringBoot), DB를 따로 빌드할 수 있게 파라미터로 설정하여 해당 파트만 따로 빌드하며 문제를 해결
  • 프론트엔드 팀원으로부터 분리 설계가 가능해 쾌적하게 개발할 수 있었다는 평가를 받음
3. 인덱스 적용을 통해 조회 속도 향상

? 부하 테스트 중 데이터가 많아질수록 post·section 조회 속도가 느려지는 것을 발견했습니다.

Post 테이블의 복합 인덱스(post_id, post_date, couple_id)를 적용해 속도 향상

  • 100만 건의 데이터를 기준으로 테스트했을 때 1200ms → 890ms로 약 25% 성능 향상을 이룸

Troubleshooting

1. 서비스 목적에 최적화된 에이전트 아키텍처 선정 및 설계

? AI-Agent를 개발할 당시 알맞은 에이전트 아키텍처 선정에 있어서 고민이 있었습니다.

복잡한 로직 설계와 실시간 처리를 결합한 LangGraph를 선정

  • StateGraph와 Conditional Edge 기능으로 복잡한 상태 관리가 쉽고 답변 정확도를 올려주며 실시간 응답이 가능한 장점으로 LangGraph를 선정
  • 총 13가지의 Conditional Edge와 22가지의 상태필드로 예상되는 LangChain 대비 코드 복잡도 25% 감소, 컨텍스트 토큰 소비량 약 15% 절감
2. 정확도 35% 향상

? AI-Agent와 대화 시 질문 해석과 답변 응답이 정확하지 않음을 발견했습니다.

텍스트 파싱 방식에서 JSON 매핑 방식 및 실시간 날씨 API를 통해 자동으로 시간 정보 입력

  • 1대1 매핑 방식인 텍스트 파싱에서 카테고리별 JSON 매핑 방식으로 전환해 정확도 60% → 95% (35%↑)
  • TPO 시간정보를 실시간 날씨 API와 연동해 자동으로 날씨까지 포함해 답변, 평균 재추천 횟수 3회 → 1.5회로 감소
3. 응답속도 60% 향상

? AI-Agent 응답 속도가 느리고 처리 단계를 알 수 없는 문제를 발견했습니다.
