Troubleshooting

1. 근거 없는 질문에 답을 지어내던 RAG 환각 차단

? 관련 문서가 없는데도 AI가 답을 만들어 냈습니다 — 상위 8개 조각을 무조건 문맥에 넣어 무관한 조각이 항상 들어갔고, 「근거가 없으면 모른다고 답하라」는 분기가 실행되지 않았습니다.

실제 문서로 유사도 분포를 재서 근거 문턱을 정하고 적용

  • 문서 4건 · 질문 10개를 실측해 근거 있는 질문 최저 0.327 / 없는 질문 최고 0.282로 갈리는 것을 확인하고 문턱을 0.30으로 설정
  • 문턱 판정을 재랭킹보다 먼저 하도록 순서를 바꿔 부작용을 해결 → 실측 질문 10개 모두 올바르게 분류
2. 품번을 놓치던 검색을 하이브리드 검색으로 개선

? 품번 · 전표번호처럼 글자가 정확히 맞아야 하는 질문에서 문서를 찾지 못했습니다 — 벡터 결과가 한 건이라도 있으면 전문 검색을 건너뛰었고, 조사가 붙은 낱말은 다른 토큰이 되어 AND 검색에서 탈락했습니다.

벡터 · 전문 검색 · 부분 일치를 합산하는 하이브리드 검색으로 재설계

  • 세 검색의 순위를 RRF(k=60)로 합치고 질의를 AND → OR로 완화, 품번 일부는 pg_trgm 부분 일치로 보완
  • 상위 24개 후보를 LLM이 재랭킹해 8개만 남기고, 평가 도구(재현율@8 · MRR)로 효과를 검증
3. 합계 질문에 답 없이 끝나던 AI 응답 문제 해결

? 「8월 손익 요약해 줘」 같은 질문에 AI가 답을 내지 못하고 종료됐습니다 — 모델이 전표 행을 직접 더하려다 도구를 20번 호출했고, 턴당 도구 단계 한도(6)에 걸렸습니다.

합계를 모델이 아니라 DB가 계산하도록 구조 변경

  • 도구에 집계 입력(group · sum)을 추가해 원천 DB에서 GROUP BY로 합계를 계산 (값은 바인딩)
  • 마지막 단계에서는 도구 호출을 막고 글로 답하게 해 답 없이 끝나는 턴을 제거
4. 부하 테스트로 찾은 로그인 병목 해소

? 1차 부하 테스트에서 2 vCPU 서버가 동시 사용자 약 130명에서 붕괴했습니다 — 로그인이 DB 커넥션을 잡은 채 bcrypt(약 55ms)를 실행해 풀이 고갈됐고, 폭주 시 bcrypt가 CPU를 독점했습니다.

비밀번호 대조를 트랜잭션 밖으로 분리하고 동시 실행 수를 제한

  • @Transactional을 걷어 bcrypt를 커넥션 없이 실행하고 세션 발급만 짧은 트랜잭션으로 분리 (Hikari 풀 10 → 25, 대기 30초 → 3초)
  • 세마포어(허가 4)로 동시 대조 수를 묶어 초과 시 503으로 빠르게 응답, Nginx에서 IP당 분당 20건으로 제한
5. AI 도구 승인의 동시 요청 중복 실행 차단

? 같은 승인이 동시에 들어오면 도구가 두 번 실행될 수 있었습니다 — 승인 상태를 SELECT로 확인한 뒤 UPDATE하는 구조라, 두 요청이 모두 「대기 중」을 읽고 각각 실행할 수 있었습니다.

조회와 변경을 한 문장으로 합쳐 승인을 선점

  • 「UPDATE … WHERE status = 'proposed' RETURNING」 한 문장으로 선점 → 동시 3요청 테스트에서 1건만 실행됨을 확인
  • 실행 입력은 클라이언트 값이 아닌 서버가 기록해 둔 입력을 사용해 승인 내용 위조를 차단
